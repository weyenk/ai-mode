## coder (adversarial) review

### Blocking

- **Exit codes vs. acceptance criterion are contradictory.** The CLI surface section defines `0 ready, 2 not-ready, 3 paused`, but the acceptance criterion states that a run "exits 0 with ... one of `ready | not-ready | paused`." As the implementer, I must guess whether a not-ready or paused run actually returns 0 (AC) or 2/3 (CLI section). This breaks every shell/test that keys off the exit code.
- **Self-heal / not-ready re-run is not executable as specified.** The must-have "Not-ready verdict: self-heal" + "Hard cap on rounds" + AC "the loop re-runs up to the round cap and logs each decision with rationale" give no concrete re-run trigger, no owner for *executing* the re-run (the role "decides within its remit" but nothing says the meeting loop restarts), and no way to represent a *split* story (architect's remedy) inside the Example Map schema (single `story` string, no `split_into[]`). I cannot build a loop that both "re-runs" and "splits" with the defined data model.
- **Layer plan has no author/owner.** `qa` classifies `test_layer` (Stage B) and the map carries `layer_plan[]`, but "writing-plans (architect) builds the stack from it" and the adversarial review step means *coder* is the one who must execute the stack. Nothing specifies who *produces* `layer_plan[]` during the meeting, so as coder I don't know whether the plan's `applies/skip` decisions are qa's output, architect's, or a third pass — and my adversarial review has no defined scope against an author-less artifact.
- **Round semantics are undefined, breaking both the round cap and `--rounds N`.** "At least two rounds" + "Hard cap on rounds" + `--rounds N` + "re-ask each parked question once." Is `--rounds` (a) per-role passes, (b) full product→qa→architect cycles, or (c) total turns? With three roles, "at least two rounds" is 2 or 6 model calls depending on interpretation. The self-heal re-run and the park/re-ask "once" each consume rounds, but the cap accounting is unspecified, so I cannot implement a deterministic stop condition.
- **`--resume` is unimplementable from the defined state.** `map.json`/`decisions.jsonl`/`parked.jsonl` are listed, but there is no round counter, no "which role last spoke," no "delta since last role," and no pointer to the current turn. Resuming "a paused meeting" (an escalated, human-resolved state) requires persisting the in-flight conversation position; the artifact list cannot reconstruct it. I would be forced to invent the resume model.
- **Invasive edits to shared Go files are under-specified for a "smallest change."** The repo-changes section mandates adding a command to `internal/app/` plus `completions/_ai-mode`, `README.md`, `AGENTS.md`. The spec never names the entrypoint file, the command-registration pattern, the completion-generation mechanism, or where a subcommand is wired in `internal/app`. As the person editing the Go CLI, I have to discover the entire registration surface before I can place `amigos`, and the spec's "one skill ↔ one tool call" + "wrapped by a thin skill" is ambiguous about whether the skill is a separate binary, a subcommand, or a config profile.

### Non-blocking

- **Uncertainty scoring is specified as a formula with no inputs.** "self-consistency (same question sampled N times)" gives no `N`; logprobs are flagged as an open spike; "above threshold → park" gives no threshold and no metric. I can only stub the score and hard-code a threshold, which the AC ("Given a question over the uncertainty threshold") then depends on. Needs a concrete N/threshold or an explicit "use default X, configurable" so the flow is testable.
- **`disagreements[]` has no schema and no producer.** It's in the Example Map but no role/round is said to populate it, and cross-role disagreement is also uncertainty input (2). I don't know what a disagreement entry looks like or when it's recorded.
- **`--profile P`, `--caller C`, `--out FILE`, `--json` are declared but never defined.** No meaning, defaults, or interaction with the intake contract (`provenance`/`authorization`). In particular `--caller C` overlaps `provenance`+`caller id` — I'd guess whether they're the same field or redundant.
- **Layer 10 "exposed surfaces" is a judgment with no input.** No definition of "exposed surface," no field in the map/intake to declare one, and no owner for the call. I'll be guessing per story.
- **Stacked-PR mechanics are explicitly un-read and deferred** ("links not yet read; read before specifying stack mechanics"), yet `writing-plans` must "build the stack from it." As the eventual executor of the adversarial review, I'm expected to judge PR ordering/mergeability that the spec has not yet specified.
- **Audit `summary` content vs. artifacts is partially inconsistent.** `summary` is described as "map, decision log, parked-question history, verdict" (all already in `map.json`/`decisions.jsonl`/`parked.jsonl`), while `transcript.jsonl` is "(full only)." So `summary` writes nothing new? The AC only tests `full`/`off`. I'd assume `summary` == default artifact set, but that's a guess.
- **Intake `--story FILE|-` vs. "story may also be a positional string" and the JSON intake contract are three encodings of one input** with no precedence rules. As the parser author I must decide how a bare positional string, a FILE, `-` (stdin), and a JSON contract coexist.
- **Hard cap value is unspecified** ("Hard cap on rounds") — separate from `--rounds N`. I need the default cap number or it's a config I invent.
- **Layer 2 bundles `unit` + `mutation` + static security as one gate/PR** but mutation "as a gate" and static security have no separate pass/fail criteria; I can't tell if mutation below a score fails the PR.
- **`--json` emits "the artifacts" but which and in what shape** (the pair `map.json`/Markdown? all four files?) is not stated.

### Proposed edits

1. **Reconcile exit codes.** Change the acceptance criterion to: "…exits 0 for `ready`, 2 for `not-ready`, 3 for `paused` (see CLI surface)." Single source of truth.
2. **Define the re-run/split loop.** Specify: (a) the meeting loop re-enters at `product` after a not-ready verdict, consuming one round; (b) architect's split produces `split_into[]` story references (or a follow-up meeting_id) rather than mutating the single `story`; (c) name the owner that *drives* the re-run (the skill wrapper / a loop controller), distinct from the role that *decides* the fix. Add `split_into[]` to the Example Map schema.
3. **Pin round semantics.** State explicitly: "`--rounds N` = N full product→qa→architect cycles; minimum 2; the self-heal re-run and each park re-ask each consume one cycle from the same budget." Give a default cap (e.g., `--rounds` default and a hard max).
4. **Assign `layer_plan` authorship.** State that `qa` produces the initial `layer_plan[]` via `test_layer`, `architect` may revise/annotate feasibility, and `writing-plans` consumes it — so the adversarial reviewer has a named author to challenge.
5. **Make resume reconstructible.** Add to state: `round.json` (current cycle + role), `delta.json` (since-last-role), and store the current turn pointer in `map.json`; specify that `--resume` re-hydrates the conversation from `map.json` + `decisions.jsonl` + `parked.jsonl` and continues at the recorded role.
6. **Name the Go integration points.** Add to repo-changes: the exact entrypoint file in `internal/app/` where the subcommand registers, the completion generator to update, and a one-line description of how `amigos` attaches (subcommand vs. profile), so the edit is a localized change rather than a discovery task.
7. **Concretize uncertainty (non-blocking but unblocks ACs).** Fix `N` (e.g., 3) and a default `park_threshold` with a config knob; specify the score formula (e.g., agreement ratio blended with logprob confidence when available, disagreement as a tie-breaker) and what a `disagreements[]` entry is.
8. **Define intake precedence.** One rule: positional string > `--story -` (stdin) > `--story FILE` > JSON contract; `--caller` populates `provenance.caller_id`; state the mapping.
9. **Define "exposed surface"** as an explicit field in the intake contract (`constraints.exposed: bool`) or a list, so layer 10 is derivable, not guessed.
10. **Clarify `summary` audit output** (writes `map.json` + `decisions.jsonl` + `parked.jsonl`, no `transcript.jsonl`) so the default is unambiguous.
