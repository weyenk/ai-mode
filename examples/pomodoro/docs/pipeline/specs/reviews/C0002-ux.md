## ux review
**Blocking**
- None. The spec defines a closed system with no ambiguity in behavior, flow, or failure mode.

**Non-blocking**
- None. There are no latent ambiguities in the terminal interaction model because the rules for session transitions, interruptions, and invalid input are specified completely.

**Proposed edits**
- The goal is too vague for a terminal product spec. Replace the first paragraph with:
  - “The goal is to present a single-line countdown timer with session type, remaining time, and session count in a minimal terminal surface.”
- The session transition rule is unclear. Replace R4 with:
  - “After every fourth completed focus session, the next session is a long break. Otherwise, the next session is a short break.”
- The summary on exit is too weak. Replace R7 with:
  - “On exit, print one line to stdout: `Completed [X] focus sessions` where [X] is the total count of finished focus sessions.”
- The invalid input rule is incomplete. Add:
  - “If any session length is negative, print `Error: session duration cannot be negative` to stderr and exit with code 1 before starting the timer.”
